# نظام الحضور والرواتب

تطبيق ويب لإدارة حضور الموظفين ورواتبهم، يطابق معادلات ملف الإكسل الحالي.
الواجهة بالعربية واتجاهها من اليمين لليسار. العملة هي الريال العماني بثلاث منازل عشرية.

- **التقنيات:** Next.js 15 (App Router)، TypeScript، Tailwind، ومكوّنات بأسلوب shadcn/ui (Radix + cmdk)، Prisma، PostgreSQL للإنتاج وSQLite للتطوير، وRecharts للرسوم.
- **الحسابات:** كلها في الخادم، داخل دوال نقية في [`src/lib/payroll.ts`](src/lib/payroll.ts)، ومغطاة باختبارات Vitest.
- **الصلاحيات:** مدير (قراءة وكتابة)، ومشاهد (قراءة فقط).

---

## 1) التشغيل محليًا

المتطلبات: Node.js 20 أو أحدث.

```bash
cd hr-payroll
npm install
cp .env.example .env          # DATABASE_URL="file:./dev.db" و AUTH_SECRET
npx prisma db push            # إنشاء قاعدة SQLite في prisma/dev.db
npm run db:seed               # بيانات تجريبية (اختياري)
npm run dev                   # http://localhost:3000
```

البيانات التجريبية (`npm run db:seed`) فيها:

- 25 موظفًا و3 سواق (سايق 1..3، بالأرقام D001..D003، وأجرة كل منهم 15).
- شهر 10/2026 كاملًا بحالات حضور عشوائية.
- أسطر إضافي ومكافآت وخصومات.
- مستخدمان:
  - مدير: `admin@example.com` / `Admin@12345`
  - مشاهد: `viewer@example.com` / `Viewer@12345`

> ⚠ الـ seed يمسح بيانات قاعدة التطوير قبل الزرع. لا تشغّله على قاعدة الإنتاج.

## 2) إنشاء أول مستخدم مدير

```bash
npm run create-admin -- you@company.com "كلمة-مرور-قوية" "اسمك"
# مستخدم مشاهد:
npm run create-admin -- viewer@company.com "كلمة-مرور" "الاسم" viewer
```

إذا كان البريد موجودًا يُحدَّث المستخدم (تتغير كلمة المرور والصلاحية).
في الإنتاج شغّل الأمر من جهازك، بعد ضبط `DATABASE_URL` على قاعدة الإنتاج.

## 3) الاستيراد من ملف الإكسل الحالي

```bash
npm run import-xlsx -- "/المسار/إلى/الملف.xlsx" --reset
```

- يقرأ الجداول بالاسم: `tblEmp` و`tblGrid` و`tblOT` و`tblDed`، ويتجاهل الأعمدة المحسوبة ثم يعيد حسابها.
- `--reset` يمسح الموظفين والحضور والسجلات الحالية قبل الاستيراد، وبدونه يرفض السكربت العمل إذا كانت القاعدة غير فارغة.
- `--dry-run` يقرأ الملف ويطبع الملاحظات فقط، دون أن يكتب شيئًا.
- بعد الاستيراد يقارن صافي كل موظف مع القيم المحفوظة في الإكسل:
  - من ورقة «الكشف الشهري».
  - ومن جدول «لوحة_الموظفين».
- **يفشل** (رمز الخروج 1) إذا تجاوز أي فرق 0.001.

> الإكسل لا يحفظ قيمًا محسوبة إلا للشهر المختار في كل ورقة لحظة الحفظ. لذلك تجري المقارنة لهذا الشهر.

النتيجة على ملفك الحالي (شهر 10/2026): **56 مقارنة، وأكبر فرق 0، ولا إخفاقات.**

## 4) الاختبارات

```bash
npm test                      # Vitest — قواعد الحساب (القسم 3) والاختبارات الإلزامية
npm run build && npm run test:e2e   # Playwright — المسار الكامل
```

اختبار Playwright:

- يستخدم قاعدة مؤقتة خاصة به (`prisma/e2e.db`) ومنفذًا مستقلًا (3100).
- يمر بالمسار كاملًا: إضافة موظف، ثم حضور شهر جديد، ثم إضافي وخصم، ثم التحقق من الصافي في الكشف الشهري ولوحة التحكم.
- ويتحقق أيضًا من تصدير Excel، ومن أن المشاهد للقراءة فقط.

لقطات الشاشة: شغّل الخادم، ثم `npm run screenshots`، فتُحفظ اللقطات في `docs/screenshots/`.

## 5) النشر على Vercel مع Neon أو Supabase

1. أنشئ قاعدة PostgreSQL على [Neon](https://neon.tech) أو [Supabase](https://supabase.com)، وانسخ رابط الاتصال.
   - في Supabase استخدم رابط «Session pooler» أو الرابط المباشر، لا رابط Transaction pooler.
2. في Vercel: **Add New → Project**، واختر المستودع، واجعل **Root Directory** = `hr-payroll`.
3. أضف متغيرات البيئة:
   - `DATABASE_URL` = رابط PostgreSQL.
   - `AUTH_SECRET` = نص عشوائي طويل (32 حرفًا على الأقل)، ويمكنك توليده بالأمر `openssl rand -base64 48`.
4. اجعل **Build Command** = `npm run vercel-build`. هذا الأمر:
   - يولّد مخطط PostgreSQL من نفس `schema.prisma`.
   - يطبّقه على القاعدة (`prisma db push`، ولا يحذف بيانات؛ يتوقف إذا كان التغيير هدّامًا).
   - ثم يبني التطبيق.
5. بعد أول نشر أنشئ المدير من جهازك:

   ```bash
   npm run db:use-postgres
   npx prisma generate --schema prisma/postgres/schema.prisma
   DATABASE_URL="postgresql://..." npm run create-admin -- you@company.com "كلمة-مرور" "اسمك"
   # (اختياري) استيراد ملف الإكسل:
   DATABASE_URL="postgresql://..." npm run import-xlsx -- file.xlsx --reset
   npx prisma generate            # للعودة إلى عميل SQLite محليًا
   ```

## 6) النسخ الاحتياطي اليومي

- `npm run backup`:
  - مع SQLite: نسخة متسقة (`VACUUM INTO`).
  - مع PostgreSQL: `pg_dump`.
  - تُحفظ النسخ في `backups/`، ويُحتفظ بآخر 30 نسخة.
- مهمة GitHub Actions يومية في [`.github/workflows/hr-payroll-backup.yml`](../.github/workflows/hr-payroll-backup.yml):
  - تعمل الساعة 03:17 بتوقيت مسقط.
  - تأخذ `pg_dump` وتحفظه 30 يومًا.
  - تحتاج سرًّا في المستودع باسم `HR_DATABASE_URL`.
  - (Neon وSupabase يوفران أيضًا استرجاعًا لنقطة زمنية.)

## قواعد العمل المعتمدة

القرارات المفتوحة (القسم 8) كما أكّدتَها:

| القرار | المطبَّق |
|---|---|
| نسبة الحضور | أيام الحضور ÷ **أيام العمل** في الشهر، أي بدون الجمعة. مثال: أكتوبر 2026 فيه 26 يوم عمل. عمود «أيام الشهر» في لوحة التحكم صار «أيام العمل». |
| إضافي في يوم غياب | يظهر تنبيه «⚠ الموظف مسجّل غائب في هذا اليوم» في عمود حالة الربط. لا يمنع الحفظ ولا يغيّر الحساب. |
| السلفة | تُخصم كاملة في شهر تاريخها، كما في الإكسل. |
| رصيد الإجازات | 30 يومًا سنويًا لكل موظف (`Settings.annualLeaveEntitlement`). يظهر المتبقي في الكشف الشهري (عمود «المتبقي من رصيد 30») وفي نموذج الإجازة. |

### سلوكيات تستحق الانتباه

- **التكرار:** لا يمكن إنشاء سطرين لنفس الموظف في نفس الشهر من التطبيق (قيد فريد في القاعدة). المكرر القادم من الاستيراد يُحفظ ويُلوَّن بالأحمر، وتُجمع عدّاداته كما يفعل `SUMIFS` في الإكسل.
- **أدوات التعبئة السريعة:** تملأ الخانات الفارغة فقط، ضمن مدة خدمة الموظف. «تعبئة الموظف» تتخطى الجمعة.
- **الحذف:** لا يوجد حذف للموظفين. أسطر الإضافي والخصم يمكن حذفها حذفًا منطقيًا فقط (soft delete)، فيبقى السجل في القاعدة وفي سجل التدقيق.
- **سجل التدقيق:** كل تعديل يُسجَّل (من، ماذا، متى، والقيمة قبل وبعد)، ويُعرض في شاشة «سجل التدقيق».
- **التصدير:**
  - Excel يُبنى في الخادم لكل جدول.
  - PDF يتم عبر طباعة المتصفح بتنسيق A4 أفقي (زر «PDF» أو «طباعة / PDF»)، لأنها الطريقة الأدق لعرض الخط العربي.
- **الربط بالمعرّف:** الربط في كل السجلات بمعرّف الموظف لا باسمه، لذلك تعديل الاسم لا يكسر أي سجل.

### فروق عن الإكسل في حالات حدّية

- **سطر خصم بلا بند:** الإكسل كان يجمع مبلغه في الخصومات. التطبيق لا يحتسبه لأن «السطر الناقص لا يدخل في أي حساب».
- **رمز في يوم غير موجود في الشهر** (مثل 31 نوفمبر): الإكسل كان يعدّه. التطبيق يقفل هذه الخانات، والاستيراد يتجاهلها ويطبع تنبيهًا.
- **ورقة «عاصم»:** لا تُستورد، لأنها خارج الجداول المذكورة في المواصفات.

```
├─ prisma/schema.prisma        نموذج البيانات (SQLite؛ وPostgreSQL عبر db:use-postgres)

├─ src/app/(app)/…             الشاشات: لوحة التحكم، الكشف الشهري، إدخال الحضور، بيانات الموظفين، سجل الإضافي، سجل الخصم، نموذج الإجازة، سجل التدقيق

├─ scripts/import-xlsx.ts      الاستيراد من الإكسل والمقارنة
├─ scripts/create-admin.ts     إنشاء مستخدم
├─ scripts/backup.ts           النسخ الاحتياطي
├─ tests/unit                  Vitest
└─ tests/e2e                   Playwright
```
